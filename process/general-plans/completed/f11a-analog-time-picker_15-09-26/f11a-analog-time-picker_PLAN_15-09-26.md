## 3. `src/lib/utils/time-of-day.ts` — the pure module

This is the **client-side** validation boundary. Say it plainly: **the server is still the real
guard.** This module only decides what string the input is allowed to hold.

### Exported API (this is the whole surface — add nothing else)

```ts
export const DAY_MINUTES = 1440

/** Parse any user-typed string to minutes-from-midnight. null = not a valid time. */
export function parseTime(raw: string): number | null

/** minutes-from-midnight -> 'HH:MM' (always 2+2 digits, never seconds). */
export function formatTime(min: number): string

/** '' for blank, 'HH:MM' for a parseable time, null for junk (the caller decides what junk means). */
export function normalizeTime(raw: string): string | null

/** Clock-face maths. */
export function angleToMinute(dx: number, dy: number): number   // 0..59, from centre offset
export function angleToHour(dx: number, dy: number): number     // 0..11, from centre offset
export function handAngle(value: number, steps: number): number // degrees, 12 o'clock = 0
```

`parseTime` contract — trim first, then match:

| Input | Result | Note |
|---|---|---|
| `''` | `null` | empty is not a time; callers treat it as "cleared" (D4) |
| `'   '` | `null` | whitespace-only collapses to empty |
| `'09:00'` | `540` | the canonical shape |
| `'9:00'` | `540` | 1-digit hour accepted |
| `'8'` | `480` | bare hour → `H:00` |
| `'12'` | `720` | 2 digits are always `HH:00` |
| `'23'` | `1380` | |
| `'93'` | `null` | 2 digits are never `H MM`; hour 93 is out of range |
| `'8:'` | `480` | trailing separator, no minutes → `H:00` |
| `'123'` | `83` | 3 digits → `H MM` (`01:23`) — regex backtracks the hour to 1 digit |
| `'830'` | `510` | 3 digits → `H MM` |
| `'0830'` | `510` | 4 digits → `HH MM` |
| `'0900'` | `540` | |
| `'8.30'` / `'8 30'` | `510` | `.` and space are separators too |
| `'09:0'` | `null` | a 1-digit minute is not accepted (a partial keystroke) |
| `'24:00'` | `null` | out of range; 1440 is not a wall-clock time |
| `'23:59'` | `1439` | the ceiling |
| `'25:61'` | `null` | both fields out of range |
| `'12:60'` | `null` | minute ceiling is 59 |
| `'-1:00'` | `null` | `-` is not a digit; no sign handling |
| `'abc'` / `'9:aa'` | `null` | non-numeric |
| `'09:00:30'` | `null` | seconds are rejected outright (D3) — never silently truncated |
| `'09:00 '` | `540` | trailing whitespace trimmed |
| `'00:00'` | `0` | midnight is valid, and is NOT the same as empty |

Implementation shape: one regex `^(\d{1,2})[:. ]?(\d{2})?$` after `trim()`, take the first match,
then a range check `h<=23 && m<=59` (missing minutes = 0). A match that fails the range check is
`null` — do not try another split. No locale parsing, no AM/PM parsing in the typed input — AM/PM is a
popover control only (D2).

`normalizeTime(raw)`:
- `raw.trim() === ''` → `''` (D4: empty must survive)
- `parseTime(raw)` non-null → `formatTime(that)`
- otherwise → `null` (junk). **The module never turns junk into `''`.** The component (§4) treats
  `null` as "do not write `value`" while typing and "revert to the current `value`" on blur. So a
  typo can never clear a punch.

`formatTime(min)` — `String(h).padStart(2,'0') + ':' + String(m).padStart(2,'0')`. Wrap the input by
`DAY_MINUTES` (`((min % 1440) + 1440) % 1440`) so a wrapped drag or an AM/PM toggle cannot produce
`24:xx` or a negative time.

`angleToMinute(dx,dy)` — `Math.atan2(dx, -dy)` gives radians clockwise from 12. Convert to degrees,
add 360 and mod 360, divide by 6, round, mod 60. `angleToHour` is the same over 30° steps, mod 12.
`handAngle(value, steps)` = `value * 360 / steps`.

### Server validation reality (state, do not fix)

| Server | Current validation | Gap |
|---|---|---|
| `attendance/+page.server.ts:222-225,254-257` | `z.string().optional()` | **no format check** — any string reaches `new Date()` |
| `timesheets/+page.server.ts:177-186` | same shape via JSON `entries` | **no format check** |
| `settings/schedules/+page.server.ts:41-45` | `hhmmToMin` regex `/^(\d{1,2}):(\d{2})$/` | rejects `''` → 400; module-private |
| `recruitment/applicant/+page.server.ts:57-59,90` | `z.string().min(1)` | **no format check**, and `new Date(\`${date}T${time}\`)` has **no timezone suffix** |

Because two servers have no format validation, the component must only ever write `''` or `HH:MM`
into `value`. `normalizeTime` returning `null` for junk, and the component refusing to write `null`,
is what keeps `new Date()` from producing `Invalid Date` **and** keeps a typo from clearing a punch.

## 4. `src/lib/components/ui/TimePicker.svelte`

### Prop contract

```ts
interface Props {
  value: string                    // bindable, always '' or 'HH:MM'
  name?: string
  form?: string
  id?: string
  required?: boolean
  disabled?: boolean
  class?: string                   // merged onto the <input> via cn()
  placeholder?: string             // default '--:--'
  'aria-label'?: string
  oninput?: (v: string) => void    // fires after every write to value (TimesheetModal recalcRow)
  onkeydown?: (e: KeyboardEvent) => void  // called from the <input>'s own keydown listener only
  [key: `data-${string}`]: string | number // data-r / data-c pass-through to the <input>
}
```

`value` is declared `$bindable('')`. This satisfies **both** call styles:

- plain `bind:value={row.timeIn}` (TimesheetModal)
- Svelte 5 function binding `bind:value={() => get(), (v) => set(v)}` (attendance) — function
  bindings work against any `$bindable` prop (Svelte 5.56.4 installed), so no second API is needed.

Schedules and applicant pass `bind:value` to page `$state` (§8.3, §8.4).

### Rendered markup

```
<span bind:this={wrapper} class="relative inline-flex">   ← anchor for measurement, no layout of its own
  <input bind:this={input} type="text" inputmode="numeric" autocomplete="off"
         {name} {form} {id} {required} {disabled} {placeholder} {...dataAttrs}
         bind:value={text}
         oninput={onInput} onblur={onBlur} onkeydown={(e) => onkeydown?.(e)}
         class={cn(base, klass)} />
  <button type="button" class="absolute right-1 ..." aria-label="Open clock"
          aria-haspopup="dialog" aria-expanded={open} onclick={toggle}> {clock icon} </button>
  {#if open}
    <div role="dialog" aria-label="Choose time" class="fixed z-[70] ..."
         style="top: {pos.top}px; left: {pos.left}px"> {clock face} </div>
  {/if}
</span>
```

- `type="button"` on the toggle and on every popover button is mandatory — every instance lives
  inside (or is associated with) a `<form>`; a default `submit` would post it.
- The `<input>` is the only form participant. The popover contains no named fields.
- The popover stays a **DOM child of the wrapper** (no portal). That keeps it inside the Dialog panel
  (so the Dialog focus trap includes its buttons) and inside `wrapper` (so the outside-click
  `contains()` check works). `position: fixed` takes it out of the scrolling ancestors' clipping
  without moving it in the DOM.
- The input's own `onkeydown` is the only place the consumer's `onkeydown` is called. The wrapper
  never forwards it. `cellKeydown` reads `e.currentTarget` as the `<input>`; that stays true.

### Value flow (the D1 + D2 guarantee)

1. `text` is local `$state`, seeded once from `value`.
2. **`onInput` (every `input` event, including Playwright `.fill()`):**
   `const v = normalizeTime(text); if (v !== null && v !== value) { value = v; oninput?.(v) }`.
   - `''` writes `''` (clear, D4).
   - A parseable string writes its `HH:MM` form.
   - Junk or a partial that does not parse (`'09:0'`, `'93'`) writes nothing; `value` keeps its
     last accepted string.
   - **Partial strings that do parse do write** (`'1'` → `01:00`, `'10'` → `10:00`, `'103'` →
     `01:03`). This is accepted: the row becomes dirty mid-typing, and the final keystroke writes the
     final value. Save posts whatever `value` holds when it is clicked, which is the last parseable
     text. Typing the stored value back (`fill('09:00')` on a row stored as `09:00`) writes `09:00`
     and `isDirty` returns to false.
3. **Re-seed effect (depends on `value` only):**
   `$effect(() => { const v = value; untrack(() => { if (normalizeTime(text) !== v) text = v }) })`.
   It reads `text` inside `untrack`, so it does not re-run per keystroke. After `onInput` writes
   `value`, `normalizeTime(text) === value`, so typing is never stomped. An external change to
   `value` (a parent reset, another row's save) lands in `text`.
4. **`onBlur`:** `text = normalizeTime(text) ?? value`. Blur only tidies the displayed text:
   `'830'` → `'08:30'`; junk (`'9300'`, `'abc'`) reverts to the current `value`, which is visibly
   shown so the user sees what will be saved. Blur never writes `value` (it was already written on
   input), so a blur alone never makes a row dirty.
5. **Popover picks:** one helper `pick(min)` sets `text = formatTime(min)`, then runs the same write as
   step 2. Hour pick, minute pick, drag frames and AM/PM all go through it.
6. **Form reset (§8.3, §8.4):** a `$effect` adds a `reset` listener on `input.form` (when non-null)
   that runs `setTimeout(() => { text = value }, 0)`. Svelte's own `bind:value` reset handler sets
   `text` to `input.defaultValue` (`''`) in a microtask (`misc.js:46`); the `setTimeout` runs after
   it, so `text` ends equal to `value`. Cleanup removes the listener.
7. Nothing else writes `value`. A round-trip of `'09:00'` yields byte-identical `'09:00'`.

### Enter

`onInput` has already written `value` by the time Enter is pressed. The component does **not** handle
Enter in the input and never calls `preventDefault` on it. Implicit form submit (schedules, applicant,
attendance row with Save rendered) and TimesheetModal's `cellKeydown` Enter navigation keep working
exactly as today.

### Modularity rule

All maths comes from `time-of-day.ts`. The component holds **only** DOM state: `open`,
`mode` (`'h' | 'm'`), `text`, `pos`, `dragging`, and the handlers. No duplicated parsing.

## 5. The analog face (SVG)

### Geometry

- `viewBox="0 0 200 200"`, centre `(100,100)`, rendered at `w-56 h-56` (224 px).
- Dial circle r=92. Tick marks: 12 long ticks at 30°, 60 short ticks at 6° drawn once as a static
  `{#each}` — these never change, so they are outside any reactive expression.
- Numerals: 12 `<text>` at r=72 — `12,1..11` in hour mode, `00,05..55` in minute mode. One
  `{#each}` whose label array is `$derived(mode)`.

### Two modes, one face

- Opens in **hour** mode. Picking an hour auto-advances to **minute** mode (the standard clock-
  picker flow; one gesture per field, two gestures total).
- A small `HH : MM` header above the face doubles as the mode switch: click `HH` → hour mode,
  click `MM` → minute mode. Both are `<button type="button">`, and the active one is
  `text-primary`.

### Hands

- Hour hand: line centre→r=48, `stroke-width 5`.
- Minute hand: line centre→r=78, `stroke-width 3`.
- Both use `transform="rotate({handAngle(...)} 100 100)"`. Only that attribute is reactive.
  Ticks, numerals and the dial are static nodes — Svelte 5 fine-grained reactivity then updates
  **two attributes per drag frame**, nothing else. That is the performance rule; do not put the
  ticks inside a `$derived` array that rebuilds.
- Centre dot r=4 `fill-primary`.
- When `value` is `''` the hands point at 12:00 and the header reads `-- : --`.

### Pointer handling

One handler set on the dial `<svg>`:

- `onpointerdown` → `svg.setPointerCapture(e.pointerId)`, set `dragging = true`, apply the value at
  that point (this is also **tap-to-set**: a tap is a down+up with no move).
- `onpointermove` → if `dragging`, apply.
- `onpointerup` / `onpointercancel` → `releasePointerCapture`, `dragging = false`; if mode was
  hour, switch to minute; if mode was minute, close (value already written by `pick`).
- "apply" = read `getBoundingClientRect()`, compute `dx = (e.clientX - rect.left) * 200/rect.width -
  100` (same for dy), then `angleToHour` / `angleToMinute`, keeping the other field and the AM/PM
  half, then `pick(min)`.
- `touch-action: none` on the svg so a drag does not scroll the page.

### Minute snapping = **1 minute**

Justified against real data, not taste: attendance stores punches to the minute and the timesheet
recalc (`recalcRow`) derives regular/OT hours from the exact minute difference. A 5-minute snap
would make `09:07` unreachable by the clock and silently change payroll hours. So the drag snaps to
1 minute — and the typed input remains the fast path for exact values. The 60 short ticks give
enough visual feedback that 1-minute precision reads as deliberate.

### AM/PM control

Two small buttons (`AM` / `PM`) under the face, `aria-pressed` on the active one. The face shows
1-12; the AM/PM buttons decide which half of the day. Toggling adds/subtracts 720 minutes through
`pick`. Per **D2** this appears only inside the popover — the input text stays 24-hour.

## 6. Popover mechanics (no portal exists in this repo)

| Concern | Decision |
|---|---|
| Positioning | **`position: fixed` from the start.** Both tables sit inside `overflow-x-auto` (`attendance/+page.svelte:596,818`; `TimesheetModal.svelte:357`), the modal body is `overflow-y-auto` (`TimesheetModal.svelte:324`) and the Dialog panel is `overflow-hidden max-h-[90vh]`. An `absolute` popover would be clipped in all three. No floating-ui. |
| Coordinates | Measured once at open from `wrapper.getBoundingClientRect()` into `pos` (`$state`). Popover size is a constant `W = 240`, `H = 300` (224 px face + header + AM/PM row + padding). `top = rect.bottom + 4`; if `rect.bottom + 4 + H > innerHeight`, `top = max(8, rect.top - 4 - H)` (flip above). `left = rect.left`; if `rect.left + W > innerWidth - 8`, `left = max(8, rect.right - W)`. |
| Inside the Dialog | The Dialog backdrop is `fixed inset-0` with `backdrop-blur-sm`. `backdrop-filter` makes the backdrop the containing block for fixed descendants, but the backdrop covers the viewport at `0,0`, so viewport coordinates are still correct. The panel's `transition:scale` only applies a transform during its 120 ms open animation, before the clock can be opened. Keep the probe (§11). |
| Close on move | While `open`, a `$effect` adds `window` `scroll` (capture: `true`, so scrolls inside the table wrapper and modal body are caught) and `resize` listeners that close the popover. Cleanup removes them. Fixed coordinates are never re-measured. |
| z-index | `z-[70]`. Above TimesheetModal's Dialog (`zIndex={50}`, `TimesheetModal.svelte:289`) and the house `Dialog` default (`zIndex = 60`, `Dialog.svelte:56`); below `Toaster` `z-[100]`. |
| Focus trap | Dialog rebuilds `FOCUSABLE` per Tab from `panelEl.querySelectorAll` and filters by `offsetParent !== null`. The popover is a DOM descendant of the panel. Its buttons are children of the fixed popover `<div>`, so their `offsetParent` is that `<div>` (non-null) and they stay in the trap. Nothing to change in `Dialog.svelte`. |
| Escape | While `open`, the same `$effect` adds a **`window` `keydown` listener in the capture phase**. If `e.key === 'Escape'`: `e.stopPropagation()`, close, `input.focus()`. Capture on `window` runs before the Dialog panel's bubbling `onkeydown` (`Dialog.svelte:95-100`) no matter where focus is — on the input, the toggle, a popover button, or the Dialog panel itself (a tap on the non-focusable SVG moves focus to the panel, which has `tabindex="-1"`, so a handler on the wrapper `<span>` would miss it). When the popover is closed the listener is not registered, so Escape closes the modal exactly as today. It never calls the consumer's `onkeydown`. |
| Outside click | The same `$effect` adds `window` `pointerdown`; if `!wrapper.contains(e.target)` → close. No commit step: `value` is already written. |
| Focus restore | Escape and minute-selected close call `input.focus()`. Outside click does not steal focus back (the user clicked something else). |
| Toggle | Clicking the toggle while open closes it. Opening measures `pos`, sets `mode = 'h'`. |

## 7. Accessibility

- **The typed input is the primary a11y path, and it never requires the popover.** A keyboard or
  screen-reader user types `0900`, tabs away, and is done. The clock is an enhancement layered over
  a working text field.
- `<input>` keeps `id`, so every existing `<label for=...>` still binds. Where there is no label
  (attendance, timesheets) pass `aria-label` — `"Time in"` / `"Time out"` for attendance, and
  `"Time in, row {i+1}"` / `"Time out, row {i+1}"` for the timesheet grid.
- Toggle button: `aria-label="Open clock"`, `aria-haspopup="dialog"`, `aria-expanded={open}`.
- Popover: `role="dialog"`, `aria-label="Choose time"`.
- The SVG dial: `role="application"` is wrong here — use `role="group"` with
  `aria-label="Clock face"` and mark the svg `aria-hidden="true"` while exposing the live value in a
  `<span class="sr-only" aria-live="polite">` that reads e.g. `"9:07 AM"`. Screen readers then
  announce the value, not the geometry.
- Keyboard inside the popover, mouse never required: `Tab` cycles HH / MM / AM / PM / Done.
  With HH or MM focused, `ArrowUp`/`ArrowDown` steps the value by 1 (hour or minute) and
  `PageUp`/`PageDown` by 5 minutes, each through `pick`. `Done` and `Enter` on a popover button close
  and refocus the input. `Escape` closes (§6) and keeps the picked value — there is no cancel,
  because picks are written live.
- Coarse-pointer floor: `app.css:114` already forces `min-height/min-width: 24px` on `button` and
  `[role='button']`. The AM/PM and HH/MM buttons inherit it for free. **Do not add
  `role="button"` to the SVG** or the floor will fight the dial's sizing; the dial is already
  224 px.

```svelte
<input type="time" bind:value={row.timeIn} oninput={() => recalcRow(row)}
  data-r={i} data-c={1} onkeydown={(e) => cellKeydown(e, i, 1)} class={inputClass} />
```
After:
```svelte
<TimePicker bind:value={row.timeIn} oninput={() => recalcRow(row)}
  aria-label="Time in, row {i + 1}"
  data-r={i} data-c={1} onkeydown={(e) => cellKeydown(e, i, 1)} class={inputClass} />
```
`data-r`/`data-c` must be forwarded to the `<input>` — `cellKeydown` finds cells with
`document.querySelector('[data-r=..][data-c=..]')` and then calls `.focus()` and `.select()` on the
result. `onkeydown` must be called from the `<input>`'s own listener (§4), because `cellKeydown`
reads `e.currentTarget as HTMLInputElement` and uses `selectionStart` / `value.length`.

`oninput` fires after `value` is written (§4 step 2), so `recalcRow(row)` sees the new time and the
Reg/OT preview updates per accepted keystroke, before Save.

**`cellKeydown` change (line 246) — explicit answer:**

```ts
if (el.type === 'date' || el.type === 'time') return // keep native segment arrows
```
becomes
```ts
if (el.type === 'date') return // keep native segment arrows
```

Why: with `type="text"`, `ArrowLeft`/`ArrowRight` now move a caret inside `HH:MM`. `selStart`
returns `null` on time inputs (caught), which makes `atStart`/`atEnd` always true — that is why the
early-return existed. On text inputs they report the real caret. Dropping `'time'` gives: arrow-right
at the end of the text jumps to the next column, arrow-left at the start jumps back, mid-string arrows
move the caret. `type="date"` keeps its early-return. The trailing comment is pre-existing; keep it
with the shortened condition, do not add a new one.

The `try { t.select() } catch {}` wrapper (lines 235-239) stays — the date column still needs it.

### 8.3 `settings/schedules/+page.svelte` — 2 instances

Before:
```svelte
<input id="start" name="start" type="time" value="08:00" required
  class="mt-1 flex h-9 w-full rounded-md border border-input bg-background px-3 text-sm" />
```
After:
```svelte
<TimePicker id="start" name="start" bind:value={start} required
  class="mt-1 flex h-9 w-full rounded-md border border-input bg-background px-3 text-sm" />
```
Same for `end` with `bind:value={end}`.

State, next to `let showCreate = $state(false)` (line 10):
```ts
let start = $state('08:00')
let end = $state('17:00')
```

**Post-submit reset.** The form uses `use:enhance={createSchedule.enhance}` and
`const createSchedule = createSubmitGuard()` (line 13) with no inner handler, so on success the guard
calls `opts.update()`, which runs `form.reset()`. The form stays open (`showCreate` unchanged).
`form.reset()` restores native fields to their default values; for the TimePicker it blanks the
input DOM (no `defaultValue`) and Svelte's bind sets `text = ''`, while `start`/`end` keep their old
state. Change line 13 to:

```ts
const createSchedule = createSubmitGuard(() => async ({ result, update }) => {
	await update()
	if (result.type === 'success') {
		start = '08:00'
		end = '17:00'
	}
})
```

**Why both this callback and the TimePicker `reset` listener (§4 step 6) are needed — neither alone
works:**
- State reset alone: if the user left Start at `08:00`, `start = '08:00'` is a no-op, the
  `value` effect does not run, and the field stays blank while the state (and the next post) holds
  `08:00`.
- Reset listener alone: the field re-shows the old state (`09:00` if the user changed it), not the
  default. Today's native form resets to `08:00`/`17:00`.
The listener is generic (keeps `text` equal to `value` after any reset); the callback restores the
page's defaults. They do different jobs.

`required` still blocks `''` (D4) because it is a real `<input required>`. `hhmmToMin`'s regex
rejects `''` with a 400 — `required` is what stops that firing.
