# F11a — House analog time picker

**TL;DR** — Build one component, `TimePicker.svelte`, that renders a **real `<input type="text">`**
(so `name`, `form=`, `required` and typing all still work) plus a small clock button that opens an
**SVG analog clock** popover. Swap it into 9 places. Put the string↔minutes math in a plain
`.ts` file so vitest can test it. Remove `bits-ui`. No new test harness.

**Date**: 15-09-26
**Status**: PLANNED
**Complexity**: COMPLEX (single plan, 6 files touched, 4 screens, e2e risk)

## 3. `src/lib/utils/time-of-day.ts` — the pure module

This is the **client-side** validation boundary. Say it plainly: **the server is still the real
guard.** This module only decides what string the input is allowed to hold.

### Exported API (this is the whole surface — add nothing else)

```ts
export const DAY_MINUTES = 1440

/** Parse any user-typed string to minutes-from-midnight. null = not a valid time. */
export function parseTime(raw: string): number | null

/** minutes-from-midnight -> 'HH:MM' (always 2+2 digits, never seconds). */
export function formatTime(min: number): string

/** What the input should hold after blur: '' stays '', junk stays as typed-but-unparsed -> ''. */
export function normalizeTime(raw: string): string

/** Clock-face maths. */
export function angleToMinute(dx: number, dy: number): number   // 0..59, from centre offset
export function angleToHour(dx: number, dy: number): number     // 0..11, from centre offset
export function handAngle(value: number, steps: number): number // degrees, 12 o'clock = 0
```

`parseTime` contract — trim first, then try in this order:

| Input | Result | Note |
|---|---|---|
| `''` | `null` | empty is not a time; callers treat it as "cleared" (D4) |
| `'   '` | `null` | whitespace-only collapses to empty |
| `'09:00'` | `540` | the canonical shape |
| `'9:00'` | `540` | 1-digit hour accepted |
| `'8'` | `480` | bare hour → `H:00` |
| `'830'` | `510` | 3 digits → `H MM` |
| `'0830'` | `510` | 4 digits → `HH MM` |
| `'8.30'` / `'8 30'` | `510` | `.` and space are separators too |
| `'24:00'` | `null` | out of range; 1440 is not a wall-clock time |
| `'23:59'` | `1439` | the ceiling |
| `'25:61'` | `null` | both fields out of range |
| `'12:60'` | `null` | minute ceiling is 59 |
| `'-1:00'` | `null` | `-` is not a digit; no sign handling |
| `'abc'` / `'9:aa'` | `null` | non-numeric |
| `'09:00:30'` | `null` | seconds are rejected outright (D3) — never silently truncated |
| `'09:00 '` | `540` | trailing whitespace trimmed |
| `'0900'` | `540` | |
| `'00:00'` | `0` | midnight is valid, and is NOT the same as empty |

Implementation shape: one regex `^(\d{1,2})[:. ]?(\d{2})?$` after `trim()`, then a range check
`h<=23 && m<=59`. Reject anything the regex misses. No locale parsing, no AM/PM parsing in the
typed input — AM/PM is a popover control only (D2).

`normalizeTime(raw)`:
- `raw.trim() === ''` → `''` (D4: empty must survive)
- `parseTime(raw)` non-null → `formatTime(that)`
- otherwise → `''` (reject junk rather than send it to the server)

`formatTime(min)` — `String(h).padStart(2,'0') + ':' + String(m).padStart(2,'0')`. Clamp/modulo the
input by `DAY_MINUTES` so a wrapped drag cannot produce `24:xx`.

`angleToMinute(dx,dy)` — `Math.atan2(dx, -dy)` gives radians clockwise from 12. Convert to degrees,
add 360 and mod 360, divide by 6, round, mod 60. `angleToHour` is the same over 30° steps, mod 12.
`handAngle(value, steps)` = `value * 360 / steps`.

### Server validation reality (state, do not fix)

| Server | Current validation | Gap |
|---|---|---|
| `attendance/+page.server.ts:222-225,254-257` | `z.string().optional()` | **no format check** — any string reaches `new Date()` |
| `timesheets/+page.server.ts:177-186` | same shape via JSON `entries` | **no format check** |
| `settings/schedules/+page.server.ts:41-45` | `hhmmToMin` regex `/^(\d{1,2}):(\d{2})$/` | rejects `''` → 400; module-private |
| `recruitment/applicant/+page.server.ts:57-59,90` | `z.string().min(1)` | **no format check**, and `new Date(\`${date}T${time}\`)` has **no timezone suffix** |

Because two servers have no format validation, `normalizeTime` returning `''` for junk is what keeps
`new Date()` from producing `Invalid Date`. That is the security/robustness argument for putting
normalisation on blur, not just on submit.

## 4. `src/lib/components/ui/TimePicker.svelte`

### Prop contract

```ts
interface Props {
  value: string                    // bindable, always '' or 'HH:MM'
  name?: string
  form?: string
  id?: string
  required?: boolean
  disabled?: boolean
  class?: string                   // merged onto the <input> via cn()
  placeholder?: string             // default '--:--'
  'aria-label'?: string
  oninput?: (v: string) => void    // fires on every accepted change (TimesheetModal recalcRow)
  onkeydown?: (e: KeyboardEvent) => void  // passed straight to the <input> (cell navigation)
  [key: `data-${string}`]: string | number // data-r / data-c pass-through
}
```

`value` is declared `$bindable('')`. This satisfies **both** call styles:

- plain `bind:value={row.timeIn}` (TimesheetModal)
- Svelte 5 function binding `bind:value={() => get(), (v) => set(v)}` (attendance) — function
  bindings work against any `$bindable` prop, so no second API is needed.

For schedules the component is used **uncontrolled-style**: pass `value="08:00"` as the initial
value. See §6.3 — this makes those two instances controlled, which is a real change and is called
out there.

### Rendered markup

```
<span class="relative inline-flex">        ← anchor, no layout of its own
  <input type="text" inputmode="numeric" autocomplete="off"
         {name} {form} {id} {required} {disabled} {placeholder}
         bind:value={text}
         onblur={commit} onkeydown={...} class={cn(base, klass)} />
  <button type="button" class="absolute right-1 ..." aria-label="Open clock"
          aria-haspopup="dialog" aria-expanded={open}> {clock icon} </button>
  {#if open} <div class="absolute z-[70] ..."> {clock face} </div> {/if}
</span>
```

- `type="button"` on the toggle is mandatory — every one of these lives inside a `<form>`; a default
  `submit` would post the form.
- The `<input>` is the only form participant. The popover contains no named fields.

### Value flow (the D2 guarantee)

1. `text` is local `$state`, seeded from `value`.
2. A `$effect` re-seeds `text` from `value` **only when `value !== normalizeTime(text)`** — so an
   external reset lands, but typing `9` is not stomped mid-keystroke.
3. `commit()` on blur / Enter / popover change: `const v = normalizeTime(text); text = v;
   if (v !== value) { value = v; oninput?.(v) }`.
4. Nothing else ever writes `value`. Therefore a round-trip of `'09:00'` yields byte-identical
   `'09:00'` and `isDirty` stays false.

### Modularity rule

All maths comes from `time-of-day.ts`. The component holds **only** DOM state: `open`,
`mode` (`'h' | 'm'`), `text`, and the pointer handlers. No duplicated parsing.

## 5. The analog face (SVG)

### Geometry

- `viewBox="0 0 200 200"`, centre `(100,100)`, rendered at `w-56 h-56` (224 px).
- Dial circle r=92. Tick marks: 12 long ticks at 30°, 60 short ticks at 6° drawn once as a static
  `{#each}` — these never change, so they are outside any reactive expression.
- Numerals: 12 `<text>` at r=72 — `12,1..11` in hour mode, `00,05..55` in minute mode. One
  `{#each}` whose label array is `$derived(mode)`.

### Two modes, one face

- Opens in **hour** mode. Picking an hour auto-advances to **minute** mode (the standard clock-
  picker flow; one gesture per field, two gestures total).
- A small `HH : MM` header above the face doubles as the mode switch: click `HH` → hour mode,
  click `MM` → minute mode. Both are `<button type="button">`, and the active one is
  `text-primary`.

### Hands

- Hour hand: line centre→r=48, `stroke-width 5`.
- Minute hand: line centre→r=78, `stroke-width 3`.
- Both use `transform="rotate({handAngle(...)} 100 100)"`. Only that attribute is reactive.
  Ticks, numerals and the dial are static nodes — Svelte 5 fine-grained reactivity then updates
  **two attributes per drag frame**, nothing else. That is the performance rule; do not put the
  ticks inside a `$derived` array that rebuilds.
- Centre dot r=4 `fill-primary`.

### Pointer handling

One handler set on the dial `<svg>`:

- `onpointerdown` → `svg.setPointerCapture(e.pointerId)`, set `dragging = true`, apply the value at
  that point (this is also **tap-to-set**: a tap is a down+up with no move).
- `onpointermove` → if `dragging`, apply.
- `onpointerup` / `onpointercancel` → `releasePointerCapture`, `dragging = false`; if mode was
  hour, switch to minute; if mode was minute, `commit()` and close.
- "apply" = read `getBoundingClientRect()`, compute `dx = (e.clientX - rect.left) * 200/rect.width -
  100` (same for dy), then `angleToHour` / `angleToMinute`.
- `touch-action: none` on the svg so a drag does not scroll the page.

### Minute snapping = **1 minute**

Justified against real data, not taste: attendance stores punches to the minute and the timesheet
recalc (`recalcRow`) derives regular/OT hours from the exact minute difference. A 5-minute snap
would make `09:07` unreachable by the clock and silently change payroll hours. So the drag snaps to
1 minute — and the typed input remains the fast path for exact values. The 60 short ticks give
enough visual feedback that 1-minute precision reads as deliberate.

### AM/PM control

Two small buttons (`AM` / `PM`) under the face, `aria-pressed` on the active one. The face shows
1-12; the AM/PM buttons decide which half of the day. Toggling adds/subtracts 720 minutes.
Per **D2** this appears only inside the popover — the input text stays 24-hour.

## 6. Popover mechanics (no portal exists in this repo)

| Concern | Decision |
|---|---|
| Anchoring | `position: absolute` inside the `relative` wrapper `<span>`. No floating-ui, no measuring. |
| Vertical flip | Open **below** by default (`top-full mt-1`). If `wrapper.getBoundingClientRect().bottom + 300 > innerHeight`, open above (`bottom-full mb-1`). One measurement at open, stored in `$state`. |
| Horizontal | `right-0` when the wrapper's left edge is past 60% of the viewport width, else `left-0`. Same single measurement. |
| z-index | `z-[70]`. Above the house `Dialog` default `zIndex: 60` (so it shows inside TimesheetModal), below `Toaster` `z-[100]`. |
| Inside the house Dialog | Works because 70 > 60 and the Dialog has **no portal and no overflow clipping on the backdrop**. But the Dialog's focus trap rebuilds `FOCUSABLE` per Tab and filters by `offsetParent` — the popover is rendered inside the panel, so its buttons are already in the trap. Nothing to change in `Dialog.svelte`. |
| Escape | The popover's own `onkeydown` handles `Escape`, closes, **calls `e.stopPropagation()`**, and refocuses the `<input>`. Without `stopPropagation` the first Escape inside TimesheetModal would close the whole modal. This is the single most important detail in this section. |
| Outside click | `window.addEventListener('pointerdown', ...)` registered in a `$effect` only while `open`; if `!wrapper.contains(e.target)` → `commit()` then close. Removed in the effect cleanup. |
| Clipping in scrolling tables | `absolute` inside a `<td>` is clipped by any ancestor with `overflow-hidden`/`auto`. **Attendance and the timesheet grid both scroll horizontally.** Mitigation: the popover does not need to escape — it is 224 px wide and the columns are wide enough, and it opens on the row's own cell. EXECUTE must verify visually on both tables (see §7 agent-probe row). If it clips, the fallback is `position: fixed` with the coordinates from the open-time measurement — plan for it, but only build it if the probe shows clipping. |
| Focus restore | On close, `input.focus()`. This happens for Escape, outside-click, and minute-selected close alike. |

## 7. Accessibility

- **The typed input is the primary a11y path, and it never requires the popover.** A keyboard or
  screen-reader user types `0900`, tabs away, and is done. Say this in the review; the clock is an
  enhancement layered over a working text field.
- `<input>` keeps `id`, so every existing `<label for=...>` still binds. Where there is no label
  (attendance, timesheets) pass `aria-label` — `"Time in"` / `"Time out"` for attendance, and
  `"Time in, row {i+1}"` / `"Time out, row {i+1}"` for the timesheet grid.
- Toggle button: `aria-label="Open clock"`, `aria-haspopup="dialog"`, `aria-expanded={open}`.
- Popover: `role="dialog"`, `aria-label="Choose time"`.
- The SVG dial: `role="application"` is wrong here — use `role="group"` with
  `aria-label="Clock face"` and mark the svg `aria-hidden="true"` while exposing the live value in a
  `<span class="sr-only" aria-live="polite">` that reads e.g. `"9:07 AM"`. Screen readers then
  announce the value, not the geometry.
- Keyboard inside the popover, mouse never required: `Tab` cycles HH / MM / AM / PM / Done.
  With HH or MM focused, `ArrowUp`/`ArrowDown` steps the value by 1 (hour or minute) and
  `PageUp`/`PageDown` by 5 minutes. `Enter` commits and closes. `Escape` cancels and closes.
- Coarse-pointer floor: `app.css:114` already forces `min-height/min-width: 24px` on `button` and
  `[role='button']`. The AM/PM and HH/MM buttons inherit it for free. **Do not add
  `role="button"` to the SVG** or the floor will fight the dial's sizing; the dial is already
  224 px.

### 8.2 `TimesheetModal.svelte` — 2 instances + `cellKeydown`

Before (timeIn, ~383-394):
```svelte
<input type="time" bind:value={row.timeIn} oninput={() => recalcRow(row)}
  data-r={i} data-c={1} onkeydown={(e) => cellKeydown(e, i, 1)} class={inputClass} />
```
After:
```svelte
<TimePicker bind:value={row.timeIn} oninput={() => recalcRow(row)}
  aria-label="Time in, row {i + 1}"
  data-r={i} data-c={1} onkeydown={(e) => cellKeydown(e, i, 1)} class={inputClass} />
```
`data-r`/`data-c` must be forwarded to the `<input>` — `cellKeydown` finds cells with
`document.querySelector('[data-r=..][data-c=..]')` and then calls `.focus()` and `.select()` on the
result. If the attributes landed on the wrapper span, focus would break.

**`cellKeydown` change (line 245) — explicit answer:**

```ts
if (el.type === 'date' || el.type === 'time') return // keep native segment arrows
```
becomes
```ts
if (el.type === 'date') return
```

Why: with `type="text"`, `ArrowLeft`/`ArrowRight` now move a caret inside `HH:MM`, and `atStart`/
`atEnd` (which call `selectionStart`) **work on text inputs but throw/return null on time inputs** —
that is exactly why the early-return existed. Dropping `'time'` restores the intended behaviour:
arrow-right at the end of the text jumps to the next column, arrow-left at the start jumps back,
and mid-string arrows move the caret. This is strictly better than today, where those keys did
nothing useful for column navigation. `type="date"` keeps its early-return, unchanged.

The `try { t.select() } catch {}` wrapper (lines 235-239) stays — the date column still needs it.

### 8.3 `settings/schedules/+page.svelte` — 2 instances

Before:
```svelte
<input id="start" name="start" type="time" value="08:00" required
  class="mt-1 flex h-9 w-full rounded-md border border-input bg-background px-3 text-sm" />
```
After:
```svelte
<TimePicker id="start" name="start" bind:value={start} required
  class="mt-1 flex h-9 w-full rounded-md border border-input bg-background px-3 text-sm" />
```

**Explicit answer on the defaults:** `value="08:00"` on a native input is an *initial* value on an
uncontrolled field. `TimePicker` binds `value`, so it is **controlled** — a bare `value="08:00"`
prop would be reset by the component's own writes. So these two **must become controlled**:

```ts
let start = $state('08:00')
let end = $state('17:00')
```
declared next to the other local state in the `<script>`. The form still posts `start`/`end` by
`name`, so `+page.server.ts` is untouched.

After a successful create the form should reset to the defaults again. The current page relies on
native form reset; check whether it calls `form.reset()` or re-renders. If it uses `use:enhance`
with a reset, add `start = '08:00'; end = '17:00'` alongside. If it does a full invalidate/reload,
nothing is needed. **EXECUTE must read the surrounding submit handler before choosing.**

`required` still blocks `''` (D4) because it is a real `<input required>`. Also keep in mind
`hhmmToMin`'s regex rejects `''` with a 400 — `required` is the thing that stops that ever firing.
